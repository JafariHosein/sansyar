<a id="about"></a>
## ✨ سانس‌یار چیست؟

**سانس‌یار** یک وب‌اپ فارسی و راست‌چین برای ثبت‌نام **سانس**های سالن فوتسال است: مدیر سالن سانس منتشر می‌کند و بازیکن‌ها از روی یک لینک مشترک در **ایتا** ثبت‌نام می‌کنند.

سانس‌یار فقط به‌صورت **برنامک (Mini App) داخل پیام‌رسان ایتا** اجرا می‌شود. باز کردن همان آدرس در مرورگر عادی، فقط گیتِ «سانس‌یار فقط از داخل ایتا باز می‌شود» را نشان می‌دهد (کد ۲۰۰، بدون ریدایرکت).

ورود یکپارچه با حساب ایتاست: `initData` امضاشده و اعتبارسنجی سمت سرور. **هیچ کد پیامکی، هیچ OTP و هیچ صفحهٔ ورود جایگزینی وجود ندارد.** تنها شمارهٔ محصول، شمارهٔ همراهِ خودِ بازیکن است که یک‌بار در اولین اجرا و فقط از خودِ ایتا (`requestContact`) گرفته می‌شود، بعد از ثبت قابل تغییر نیست و فقط مدیر آن را می‌بیند.

بعد از شماره، نام و نام خانوادگی واقعی پرسیده می‌شود و تا وقتی **مدیر عضویت حساب را تأیید نکند** بازیکن هیچ کاری نمی‌تواند بکند. تأیید یک‌بار روی حساب انجام می‌شود؛ بعد از آن هر ثبت‌نام تازه مستقیم قطعی است و اگر سالن پر باشد، به لیست انتظار می‌رود.

## 🎯 امکانات

### برای بازیکن

- تابلوی سانس‌ها با سه تب «در حال ثبت‌نام / به‌زودی / گذشته» و شمارندهٔ ظرفیت
- شمارش معکوس باز شدن پنجرهٔ ثبت‌نام
- صفحهٔ جزئیات سانس: مکان، آدرس، لینک مسیریابی نشان، تاریخ و ساعت شمسی، قیمت، قوانین انصراف و فهرست شماره‌دار ثبت‌نام‌شده‌ها
- ثبت‌نام تراکنشی با قفل ردیف سانس؛ سالن پر → **لیست انتظار**
- لغو ثبت‌نام با «قانون همان لحظه» و نمایش دقیق جریمه یا آزاد بودن
- **موجودی حساب (کیف پول):** پول صندلی لغوشده به موجودی برمی‌گردد و ثبت‌نام بعدی اول از موجودی خرج می‌کند
- «ثبت‌نام‌های من» با وضعیت قطعی/لیست انتظار/لغو، پرداخت و سابقه
- پروفایل با آمار شخصی، سابقهٔ جریمه‌ها، تغییر نام نمایشی و شناسهٔ ایتا
- صفحهٔ «قوانین» با متن خوانا از تنظیمات زنده
- صفحهٔ پرداخت آزمایشی (Mock) با بنر واضح «پرداخت واقعی انجام نمی‌شود»

### برای مدیر

- داشبورد با چهار تایل: ثبت‌نام امروز، سانس بعدی، دریافت‌نشده‌های ۳۰ روز اخیر و محرومیت فعال
- صف عضویت «در انتظار تأیید» و «ردشده‌ها» با نام واقعی، شمارهٔ تماس و لینک `tel:`
- CRUD کامل سانس‌ها با پیکر تاریخ شمسی، بازهٔ ثبت‌نام، ظرفیت، قیمت، حالت پرداخت و قوانین اختصاصی هر سانس
- مدیریت هر سانس: حضور و غیاب، وضعیت پرداخت، حذف ثبت‌نام، ارتقای دستی از لیست انتظار، بستن حضور و غیاب، لغو کل سانس و اشتراک‌گذاری
- پروندهٔ کاربران: سابقهٔ کامل، محروم کردن/لغو محرومیت و تنظیم موجودی با گردش حساب
- مدیریت مکان‌ها
- تنظیمات ۱۲ قاعدهٔ پیش‌فرض با پیش‌نمایش زنده
- ارسال پیام ایتا برای رویدادهای مهم: تأیید/رد عضویت، ارتقا از لیست انتظار و جریمه

### فنی

- ثبت‌نام و ارتقا با **قفل ردیف و تراکنش**؛ بدون مسابقهٔ ظرفیت
- دروازهٔ عضویت سمت سرور؛ کلاینت فقط تعیین می‌کند کاربر چه می‌بیند
- دفتر موجودی (`BalanceEntry`) برای هر حرکت پول؛ موجودی هرگز منفی نمی‌شود
- پرداخت به‌صورت compare-and-set؛ دو تپ هم‌زمان نمی‌تواند دو بار پرداخت کند
- ذخیرهٔ زمان‌ها به UTC و نمایش شمسی در `Asia/Tehran`
- رابط کاربری RTL، فونت Estedad، اعداد فارسی و دسترس‌پذیری AA
- شبیه‌ساز ورود فقط در توسعه و حذف کامل کد آن از باندل production

<a id="rules"></a>
## 📜 قوانین کلیدی

### عضویت

- حساب تازه `PENDING` است و تا تصمیم مدیر هیچ کاری نمی‌تواند بکند.
- تأیید **یک‌بار روی حساب** انجام می‌شود، نه روی هر صندلی.
- رد شدن قطعی نیست؛ مدیر از «ردشده‌ها» می‌تواند دوباره تأیید کند.
- سرور در `registerSeat` وضعیت عضویت را زیر قفل دوباره می‌خواند و `PENDING`/`REJECTED` را رد می‌کند.

### ظرفیت و لیست انتظار

- اشغال صندلی فقط با وضعیت `CONFIRMED` محاسبه می‌شود؛ شمارندهٔ ذخیره‌شده روی سانس وجود ندارد.
- سالن پر → ثبت‌نام `WAITLIST`.
- آزاد شدن هر صندلی، اولین نفر لیست انتظار را مستقیم به `CONFIRMED` می‌برد و مهر `promotedAt` می‌زند.
- لغو از لیست انتظار همیشه آزاد است و کسی را بالا نمی‌آورد.

### انصراف و جریمه

پیش‌فرض‌ها از `/admin/settings` قابل تغییرند و هر سانس می‌تواند override داشته باشد:

- انصراف تا **۱۲ ساعت** قبل: آزاد و بدون اثر.
- انصراف دیرهنگام: اولین بار در ۱۴ روز اخیر فقط اخطار، سپس **۳ روز** محرومیت.
- غیبت بدون انصراف: **۷ روز** محرومیت.
- **۳ تأخیر در ۳۰ روز**: **۷ روز** محرومیت.
- مدیر همیشه می‌تواند دستی محروم کند یا محرومیت را لغو کند.

### کیف پول

- پول صندلی لغوشده **نقدی برنمی‌گردد**؛ به موجودی حساب برمی‌گردد.
- ثبت‌نام بعدی — حتی حضوری — اول از موجودی خرج می‌کند و فقط مانده را می‌خواهد.
- قیمت هر صندلی در لحظهٔ ثبت‌نام snapshot می‌شود (`amountToman`)؛ تغییر بعدی قیمت سانس، صندلی قدیمی را دوباره قیمت نمی‌زند.
- هر حرکت یک ردیف `BalanceEntry` می‌سازد تا دفتر و ستون موجودی همیشه یکی باشند.

### پرداخت و حضور

- صندلی **قبل از** پرداخت قطعی می‌شود؛ پرداخت هیچ‌وقت درِ صندلی نیست.
- پرداخت آزمایشی است و فقط برای ردیف قطعی و پرداخت‌نشده باز می‌شود.
- حضور و غیاب: «حاضر / تاخیر (دقیقه) / غایب»؛ «بستن حضور و غیاب» بقیهٔ صندلی‌ها را یک‌جا غایب می‌کند.

<a id="architecture"></a>
## 🏗️ معماری

```text
┌────────────────────────────────────┐
│  Eitaa Mini App (Next.js App Router)│
│  RSC + Server Actions + Client Islands│
└───────────────┬────────────────────┘
                │ initData / contact (HMAC-SHA256)
┌───────────────▼────────────────────┐
│  Server Actions                    │
│  auth / registration / cancel /    │
│  membership / attendance / balance │
└───────────────┬────────────────────┘
                │ core engines (transaction + row locks)
┌───────────────▼────────────────────┐
│  Prisma 7 + MariaDB adapter        │
└───────────────┬────────────────────┘
                │
┌───────────────▼────────────────────┐
│  MySQL 8.4                         │
└────────────────────────────────────┘
```

- `src/app/(app)/` — سطح بازیکن/مدیر با هدر چسبان و تب‌بار پایین
- `src/app/admin/` — پنل کامل مدیر با گارد سرور و نوار بخش‌ها
- `src/server/*-core.ts` — موتورهای اصلی: ثبت‌نام، عضویت، حضور و غیاب و موجودی
- `src/lib/eitaa*.ts` — پل ایتا، امضای `initData`، لینک اشتراک و پیام‌ها
- `prisma/schema.prisma` — مدل داده؛ زمان‌ها UTC و `eitaaId` به‌صورت رشته

قفل‌ها همیشه به ترتیب **session → user** گرفته می‌شوند و در تراکنش‌هایی که به چند کیف پول دست می‌زنند، شناسه‌ها صعودی مرتب می‌شوند تا دو لغو آینه‌ای به هم قفل نشوند.

<a id="quickstart"></a>
## 🚀 راه‌اندازی

### پیش‌نیازها

- Node.js 20+ و npm
- Docker برای MySQL 8.4 (یا هر MySQL/MariaDB محلی)
- یک فایل `.env` ساخته‌شده از `.env.example`

> روی ویندوز/PowerShell از `npm.cmd` و `npx.cmd` استفاده کنید؛ شیم‌های `.ps1` ممکن است توسط execution policy بلاک شوند.

### اجرا

```bash
npm install
cp .env.example .env

npm run db:up          # MySQL 8.4 روی 3306
npm run db:generate    # کلاینت Prisma — بعد از clone و بعد از هر تغییر اسکیما
npm run db:migrate
npm run db:seed        # دادهٔ دموی فارسی؛ idempotent و «امروزمحور»
npm run dev            # Turbopack → http://localhost:3000
```

سپس `http://localhost:3000` را باز کنید. طبق انتظار، گیتِ «بیرون ایتا» را می‌بینید. برای رد شدن از گیت در توسعه، از پنل «حالت توسعه» روی همان گیت استفاده کنید (بخش بعد).

> `db:generate` را فراموش نکنید: کلاینت Prisma در `src/generated/prisma` قرار می‌گیرد و git-ignore است؛ یک clone تازه بدون آن typecheck یا build نمی‌شود.

## ⚙️ متغیرهای محیطی

| متغیر | توضیح |
|---|---|
| `DATABASE_URL` | رشتهٔ اتصال MySQL؛ پیش‌فرض با `docker-compose.yml` هم‌خوان است |
| `SESSION_SECRET` | کلید امضای کوکی نشست؛ یک رشتهٔ تصادفی طولانی |
| `ADMIN_EITAA_ID` | شناسهٔ عددی ایتای مدیر؛ چند شناسه با کاما |
| `APP_URL` | آدرس عمومی برنامه برای ساخت لینک مطلق در پیام اشتراک‌گذاری |
| `EITAA_BOT_TOKEN` | توکن برنامک از پنل ایتایار؛ فقط سمت سرور |
| `EITAA_APP_USERNAME` | نام کاربری برنامک در ایتا |
| `EITAA_LINK_TEMPLATE` | قالب لینک برنامک؛ `{start}` با پارامتر شروع جایگزین می‌شود |
| `EITAA_DEV_LOGIN` | فعال‌کردن شبیه‌ساز ورود فقط در `NODE_ENV=development` |
| `EITAA_DEV_BOT_TOKEN` | توکن اختیاری برای امضای `initData` شبیه‌ساز |

> ⚠️ در مقدارهای `.env` هر `$` را به‌صورت `\$` فرار دهید. Next.js فایل را با dotenv-expand می‌خواند و یک `$NAME` تعریف‌نشده به رشتهٔ خالی تبدیل می‌شود. `npm run check:env` همین را بررسی می‌کند.

<a id="devlogin"></a>
## 🔐 ورود آزمایشی (فقط توسعه)

وقتی `NODE_ENV=development` و `EITAA_DEV_LOGIN` روشن است:

- روی گیت، پنل «ورود آزمایشی بازیکن / مدیر» را بزنید؛
- یا در کنسول مرورگر: `window.__eitaaDebugLogin("<initData>")`؛
- یا با CLI یک `initData` امضاشده بسازید:

```bash
npx tsx scripts/eitaa-sign-initdata.ts --id 100000000 --name "مدیر سانس"
```

خروجی را در کنسول مرورگر بگذارید:

```js
window.__eitaaDebugLogin("<initData>")
```

شناسهٔ سانس باید معتبر باشد: `parseStartTarget` فقط شناسه‌های ۶ تا ۶۴ کاراکتری را می‌پذیرد.

همهٔ این مسیرها از همان action واقعی و همان اعتبارسنجی سرور عبور می‌کنند. در production نه دکمه، نه هوک و نه action شبیه‌ساز وجود دارد؛ کد و متن فارسی شبیه‌ساز هم وارد باندل کلاینت نمی‌شود.

### دادهٔ دمو

`npm run db:seed` چند حساب و سانس نمونه می‌سازد. چند شناسهٔ مفید:

| کاربر | شناسهٔ ایتا | وضعیت |
|---|---|---|
| مدیر دمو | `100000000` | `ADMIN` (وقتی `ADMIN_EITAA_ID` خالی باشد) |
| مهدی توکلی | `200000005` | بدون شمارهٔ همراه — برای تست شیت اولین اجرا |
| فرهاد بهرامی | `200000017` | در انتظار تأیید |
| سجاد قربانی | `200000018` | در انتظار تأیید |
| کامران یوسفی | `200000019` | ردشده |

<a id="adminid"></a>
## 🛡️ تنظیم شناسهٔ مدیر

بعد از اولین ورود، تا وقتی `ADMIN_EITAA_ID` تنظیم نشده باشد، «پروفایل ← شناسهٔ من» شناسهٔ ایتای شما را با دکمهٔ کپی نشان می‌دهد. همان را در `ADMIN_EITAA_ID` بگذارید و سرور را ری‌استارت کنید تا تب «مدیریت» باز شود.

بعد از آن، بلوک «شناسهٔ من» فقط برای خودِ مدیر دیده می‌شود.

| `/admin` | داشبورد و صف عضویت |
| `/admin/sessions` | لیست، ساخت و ویرایش سانس‌ها |
| `/admin/sessions/<id>` | مدیریت سانس: حضور و غیاب، پرداخت، ارتقا و اشتراک‌گذاری |
| `/admin/users` | کاربران، محرومیت و موجودی |
| `/admin/venues` | مکان‌ها |
| `/admin/settings` | ۱۲ قاعدهٔ پیش‌فرض |

> صفحهٔ `/login` وجود ندارد. گیت «فقط داخل ایتا» هم route نیست؛ یک overlay کلاینتی است که وقتی `initData` خالی یا نامعتبر باشد نمایش داده می‌شود.

<a id="deploy"></a>
## 🚢 استقرار

نکات مهم برای اجرا روی سرور:

- مقصد ثبت‌شده در ایتایار باید **HTTPS و بدون ریدایرکت** باشد؛ گیت باید کد ۲۰۰ برگرداند.
- هیچ‌جا `X-Frame-Options` یا CSP `frame-ancestors` که iframe را بلاک کند ست نکنید؛ وب ایتا برنامک را داخل `<iframe>` اجرا می‌کند.
- SDK رسمی ایتا (`https://developer.eitaa.com/eitaa-web-app.js`) تنها اسکریپت خارجی پروژه است و باید توسط پل خود برنامه تزریق شود، نه با `next/script`.
- در production: `NODE_ENV=production`، `EITAA_DEV_LOGIN=0`، `SESSION_SECRET` واقعی، `DATABASE_URL` production، `EITAA_BOT_TOKEN` و `ADMIN_EITAA_ID` تنظیم‌شده و `APP_URL` دامنهٔ نهایی.
- قبل از استقرار، `npm run db:deploy` را اجرا کنید (نه `db:migrate`).
- بیلد production را با `npm run build` بسازید و با `npm run start` اجرا کنید.
